# สถานะโครงการร่วม — ระบบทะเบียนขนส่ง

## การแบ่งงาน
ใช้โฟลเดอร์เดียวกัน: Codex ออกแบบ UI และ Claude Code พัฒนาฐานข้อมูล/backend ตามคำสั่งผู้ใช้ หลีกเลี่ยงแก้ไฟล์เดียวกันพร้อมกัน อ่านไฟล์ล่าสุดก่อนเริ่มงานทุกครั้ง
ไฟล์ร่วมกันไม่ได้ซิงก์บทสนทนา และไม่ได้เผยแพร่เว็บอัตโนมัติ

## UI ปัจจุบัน
- Dashboard ภาษาไทย ข้อมูลตัวอย่างถูกล้างแล้ว ยอดงานเป็นศูนย์
- ประเภทงาน: จดทะเบียนรถใหม่, การสลับเลข, การโอน, อื่นๆ, งานแจ้งย้ายยามาฮ่า
- หน้า จดทะเบียนรถใหม่ มี 4 หัวข้อย่อย: เพิ่มข้อมูลรถจดใหม่, แจ้งย้าย/ตัดบัญชี, ตรวจรถ, ยื่นเอกสารจดทะเบียนรถใหม่ หัวข้อแรกมีฟอร์มและฐานข้อมูลรถ Single/Batch แล้ว อีก 3 หัวข้อยังว่าง
- อีก 4 ประเภทงานยังมีเฉพาะหัวข้อ รอรายละเอียดจากผู้ใช้
- ฐานข้อมูลลูกค้า: แบบฟอร์มเพิ่มลูกค้า ตารางรายชื่อ และหน้าต่างดูรายละเอียด ยังไม่มีแก้ไขหรือลบ

## สัญญาข้อมูลลูกค้า
| ชื่อช่อง | JSON key | SQL column | เงื่อนไข |
| --- | --- | --- | --- |
| ชื่อลูกค้า | name | name | จำเป็น, ไม่เกิน 250 ตัวอักษร |
| บริษัท | company | company | ไม่บังคับ, ไม่เกิน 250 |
| สาขา | branch | branch | ไม่บังคับ, ไม่เกิน 250 |
| ที่อยู่บริษัท | address | address | ไม่บังคับ, ไม่เกิน 2000 |
| เลขประจำตัวผู้เสียภาษี | taxId | tax_id | ไม่บังคับ, หากกรอกเป็นตัวเลข 13 หลัก; เก็บเป็นข้อความเพื่อรักษาศูนย์นำหน้า |
| เบอร์โทรศัพท์ | phone | phone | ไม่บังคับ, เก็บเป็นข้อความ, ไม่เกิน 250 |
| อีเมล | email | email | ไม่บังคับ, ตรวจรูปแบบ, ไม่เกิน 250 |

- GET /api/customers → {customers:[{id,name,company,branch,address,taxId,phone,email,createdAt}]}
- POST /api/customers รับ JSON ทั้ง 7 keys เป็น string พร้อม id ที่เป็น UUID; สำเร็จตอบ 201 {id}
- ช่องไม่บังคับส่ง empty string ได้
- ฝั่ง UI สร้าง UUID และใช้ซ้ำเมื่อลองบันทึกใหม่เพื่อป้องกันรายการซ้ำ
- POST ตรวจ same-origin และ application/json
- ข้อผิดพลาดตอบ {error:ข้อความภาษาไทย}; ไม่ล้างฟอร์มเมื่อบันทึกล้มเหลว

## ฐานข้อมูลและการเผยแพร่
- ใช้ Cloudflare D1 binding DB, ตาราง customers
- schema อยู่ db/schema.ts; migrations อยู่ drizzle/
- migration แรกได้เผยแพร่แล้ว ห้ามแก้ย้อนหลังเมื่อใช้ฐานเดิม
- .openai/hosting.json ผูกกับ Sites เดิม ไม่ใช่รหัสผ่านหรือข้อมูลยืนยันตัวตน
- แอปอาศัย Sites จำกัดการเข้าถึง ปัจจุบันไม่มี login/role พนักงานใน Worker เอง
- ไม่มี credentials หรือสำเนาฐานข้อมูล production ในโฟลเดอร์นี้ การเข้าถึง source ไม่ได้ให้สิทธิ์เข้าฐาน production อัตโนมัติ
- ยังไม่มี dev server/local database workflow ใน package scripts ให้สร้างได้เมื่อผู้ใช้สั่งพัฒนา backend

## ตรวจสอบที่ทำแล้ว
สร้าง Worker สำเร็จ; ทดสอบ backend กับ SQLite ในเครื่อง: บันทึก/อ่านครบ 7 ช่อง, ศูนย์นำหน้า, retry ไม่ซ้ำ, ปฏิเสธข้อมูลผิดและ cross-origin, จัดการฐานข้อมูลล้มเหลว

## บันทึกงานต่อไป
หัวข้อเพิ่มข้อมูลรถจดใหม่มี Single/Batch แล้ว ดู docs/VEHICLE-ENTRY.md

## เพิ่มข้อมูลรถจดใหม่ (อัปเดตล่าสุด)
หน้าแรกของ 4 หัวข้อมี Single/Batch ใช้งานแล้ว อ่าน docs/VEHICLE-ENTRY.md สำหรับรายละเอียด UI, API, validation และฐานข้อมูลใหม่ ส่วนอีก 3 หัวข้อยังว่างตามเดิม
