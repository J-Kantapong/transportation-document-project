# Tax renewal (ต่อภาษี), incl. transport-act vehicles

Project documentation for Claude Code and Codex. Moved here unchanged from `CLAUDE.md` on 2026-11-16 to keep that file short; `CLAUDE.md` holds the index. Update this file when the feature changes.

- Tax renewal job owner + receipt page (user 2026-10-08, migration `20261008120000_tax_renewal_receipts`): manual-entry tax renewals now pick `เจ้าของงาน` (`customerId`, required on the form; vehicle-linked jobs keep the vehicle's customer); `PATCH /api/tax-renewals/:id` also takes `customerId` (filling an empty owner is routine, changing one needs `remark` + AuditLog). New page `/registration/tax-renewal/receipt` (`TaxRenewalReceiptPage`) like the new-vehicle / move-out receipt pages: `ReceiptImage.taxRenewalId`, `POST/DELETE /api/tax-renewals/:id/receipts` (OCR, hash duplicate check), `PATCH .../receipt-fields` (`TaxRenewal.receiptNo/receiptDate/receiptAmount`, filled by OCR when all three are empty), and the first `receivedDate` now needs at least one receipt photo (confirm on the page = `PATCH :id { receivedDate }`); after receipt, photo/field edits need a remark and the last photo cannot be removed. `GET /api/tax-renewals` rows carry `receipts[]`.

- Tax renewal for รถตาม พ.ร.บ.การขนส่งทางบก (รถใหญ่ / รถประกอบการ, user 2026-11-09 "เอาข้อมูลที่ดูไม่ต้องพิมพ์เยอะ", migrations `20261109100000_transport_tax_family` (enum values only, Postgres cannot use a new enum value in the same transaction) + `20261109110000_tax_renewal_transport`, both additive): four vehicle types `ขส.-ส่วนบุคคล`, `ขส.-ไม่ประจำทาง`, `ขส.-ประจำทาง`, `ขส.-รถขนาดเล็ก` (`TRANSPORT_VEHICLE_TYPES` / `isTransportType` in `backend/src/vehicles/vehicle-reference-data.ts`, copied in `frontend/src/lib/vehicle-reference-data.ts`) exist **only for the tax-renewal form** (manual entry; `VEHICLE_TYPES` of the new-vehicle flow stays 14, `parseVehicleType` in `tax-renewal-validation.ts` accepts both lists). They start with `ขส.-`, so every car/moto rule treats them as cars (STAFF_CAR / ADMIN write, ACCOUNTANT read, car queues in Delivery / billing / search) with no scope change. Tax = บัญชีอัตราภาษีรถตามมาตรา 85 ท้าย พ.ร.บ.การขนส่งทางบก พ.ศ. 2522 (แก้ไขโดยฉบับที่ 11 พ.ศ. 2550), by **น้ำหนักรถ (tare), not น้ำหนักรวม**, one column per licence type, in `GovernmentTaxWeightBracket` under new `GovTaxVehicleFamily` values `TRANSPORT_PRIVATE / TRANSPORT_NON_FIXED / TRANSPORT_FIXED / TRANSPORT_SMALL` (`fuelGroup` null; mapping `TRANSPORT_FAMILY_BY_TYPE` in `backend/src/tax/government-tax-reference-data.ts`, `TaxMethod` `WEIGHT_TRANSPORT`, registration code `ขส.`). The ส่วนบุคคล column is identical to the RY2 table and ends at 7,001+ = 3,600; the user's real receipt (HINO 6 ล้อ, น้ำหนักรถ 7,800, จด 2548, เจ้าของ บมจ.) was 3,600, so **only `TRANSPORT_PRIVATE` is VERIFIED/active**; the other three columns are seeded DRAFT/inactive (picking them answers "ยังไม่มีตารางอัตรา…" until the user confirms a number). No juristic ×2 and no age discount (both are พ.ร.บ.รถยนต์ รย.1 rules; `juristicMultiplierFor` already returns 1 for every non-RY1 family); the 1%/month late fee is applied like cars (assumption, not confirmed); the Act's half rate for EV/NGV-only and 3/4 for NGV dual-fuel is **not built** (fuel is hidden on the form and stored as `ดีเซล`). Inspection: a ขส. vehicle must be inspected every year before the tax (`requiresInspection('ขส.', …)` is always true); the office takes the truck itself, so it is **one date**, `TaxRenewal.inspectionDate` (no ส่งตรวจ/ผลตรวจ steps, user asked for minimal typing), required before `paymentDate` (400 `TRANSPORT_INSPECTION_REQUIRED_ERROR`), not after the payment date, not after today; filling it from empty is routine, changing/clearing needs `remark` (same `WORKFLOW_DATE_FIELDS` rule), and `inspectionConfirmed` is derived from it (`inspectionConfirmedOf`); a non-ขส. row with `inspectionDate` is refused. Fees (`tax-renewal-fee.ts`): No Bill = `ค่าตรวจสภาพรถ` 1,000 (`TAX_RENEWAL_INSPECTION_FEE_TRANSPORT`, kept even when ลงขัน is skipped) + ลงขัน 100 (`TAX_RENEWAL_CONTRIBUTION_TRANSPORT`), `vehicleClassOf` → `'TRANSPORT'`; both are office costs inside `noBillItems` (Claude's choice: if a customer pays the inspection separately the accountant adds a FEE line on the bill by hand). Form (`TaxRenewalPage.tsx`, manual entry only): the ประเภทรถ select has two optgroups; picking a ขส. type hides เชื้อเพลิง / CC / ติ๊ก ตรอ. / ไฟแนนซ์, requires น้ำหนักรถ, shows วันที่ตรวจสภาพรถ (optional, fill later in the table) and presets เจ้าของ = นิติบุคคล. The list's ตรอ. column shows a `DateCell` for the inspection date on `vehicleClass === 'TRANSPORT'` rows (`GET /api/tax-renewals` rows carry `vehicleClass` CAR|MOTO|TRANSPORT + `inspectionDate`), and the payment cell reads "รอตรวจรถ" until it is set; the ✎ แก้ dialog has the date too. Deliberately not stored (user: less typing): ผู้ประกอบการขนส่ง, เลขใบอนุญาต / วันสิ้นอายุ, รหัสตรวจสภาพ, น้ำหนักรวม, ลักษณะรถ. Downstream (Delivery, other-jobs billing with `billTotal` as the FEE line, overview, activity, search) is unchanged. Unit-tested (`tax-renewal-transport.spec.ts`). Both migrations were applied to the dev database on 2026-11-09 and the whole flow (create refused without inspection date, inspection date, payment = 3,600 / 1,100, remark required to change the date, cancel) was run against the real dev backend through the API; the page itself was checked only against a throwaway fixture API (no dev login available to Claude). The cancelled test row `TEST-TRANSPORT-CLAUDE` remains on dev as a soft-cancelled TaxRenewal.
