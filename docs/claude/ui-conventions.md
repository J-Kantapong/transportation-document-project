# UI conventions: date inputs, tabs as URLs, date guards, photo sheet tool

Project documentation for Claude Code and Codex. Moved here unchanged from `CLAUDE.md` on 2026-11-16 to keep that file short; `CLAUDE.md` holds the index. Update this file when the feature changes.

- Date inputs (user's choice 2026-09-25): every วว/ดด/ปปปป box is `components/DateInput.tsx`, which keeps typing
  (each caller still formats / converts a Buddhist year as before) and adds a calendar button that opens a hidden
  native `<input type="date">` via `showPicker()` and hands back "วว/ดด/ปปปป". Use it for any new date field.
  `CashAdvancePage` (another chat's work in progress) was not converted yet.

- Underline tabs are URLs (user's choice 2026-09-25, `components/PageTabs.tsx`): `/inspection` + `/inspection/result`,
  `/entry` + `/entry/batch`, `/register` + `/register/customer` (the second route re-exports the first page, which
  picks its tab from `usePathname`), and the submitted-records car/moto tabs use `?tab=moto` so their filters stay.
  The tax-renewal "เลือกรถจากระบบ / กรอกข้อมูลรถเอง" toggle stays in-page because it is part of an unsaved form.

- Date guards (user 2026-10-13, frontend only, no migration, `frontend/src/lib/date-check.ts`): the date corrections of the last 30 days were not single typos but a few whole-batch events fixed one vehicle at a time (delivery slip DL-00001, 61 vehicles dated Saturday 26/09 instead of Monday 28/09; 54 inspection-sent dates on the 13/10 public holiday moved to 14/10; 36 submissions cancelled and resubmitted for a wrong submit date). Two guards, warnings only (the backend refuses nothing new): (1) `DateInput` takes `weekday`: the short weekday is shown after the calendar button and Saturday / Sunday is orange with "⚠" (DLT closed). Set on the dates of the inspection page, the transfer-notice page, the Step 4 submit date (`SubmitDateField`) and the Delivery page; use it on any new DLT working-day date. (2) `confirmDates(action, dates, { always, note })` opens a `window.confirm` listing the dates in words, grouped, with vehicle counts ("วันเสาร์ที่ 26/09/2026 (อีก 2 วัน) - 61 คัน") and the weekend warning: **always** before a multi-vehicle save (inspection send / result "บันทึกทั้งหมด", transfer notice "บันทึกทั้งหมด"; the old "more than one page" confirm is folded into its note) and only when the date is a weekend for a single-row save or a correction dialog. The two existing confirm dialogs (Step 4 review, Delivery) now print the weekday and the weekend warning. Public holidays are deliberately not checked (user: they change too often, weekends first). Bulk correction (user 2026-10-13 "ทำแก้วันที่หลายคัน", frontend only): the "รถที่เพิ่งส่งตรวจ (รอผลตรวจ)" table of the inspection page has a checkbox per row, a header checkbox (every vehicle in the list, other pages included) and one chip per sent date ("13/10/2026 · 54 คัน") that ticks that whole day; "แก้วันที่ส่งตรวจที่เลือก (N คัน)" opens a dialog with one new date and one mandatory reason, shows the confirm above, then calls the existing `PATCH /api/vehicles/:id/inspection-sent-correction` once per vehicle (sent type and cost unchanged, same remark in every `VehicleEditLog`, vehicles already on that date skipped, failures listed and left ticked). `ReferencePanel` takes optional `selection` + `toolbar` for this. Only the inspection-sent date has it; result date, transfer-notice date and submit date do not. Browser-checked on 2026-10-13 against a throwaway fixture server (real frontend, invented rows, no database): bulk dialog, weekend chip, confirm text, and the entry-page model hint + warning box all rendered and worked; not tested against the real backend.

- Photo sheet tool (จัดรูปลง A4, user 2026-10-09, frontend only, no backend, no migration): menu "จัดรูปลง A4" at `/tools/photo-sheet`, open to every staff role (`ALL_STAFF` in `PAGE_RULES`). Customers send the ตรวจนอก photos one by one and the office had to lay them out by hand; here staff pick or drop all the photos, optionally type a header line, reorder / rotate / remove them, see an A4 preview and save one PDF. All photos are packed onto one A4 like the office's own sample (1-2 photos one column, 3-8 two columns, 9-12 three columns, more than 12 continue on the next page; each photo keeps its proportions, centred in its cell). Everything happens in the browser (`frontend/src/lib/photo-sheet.ts`: EXIF rotation and downscale to 1,800 px on load, `jspdf` `addImage`, the Thai header is drawn on a canvas because jsPDF's built-in fonts have no Thai); nothing is uploaded or stored, so closing the page loses the photos. Claude's choices, not confirmed by the user: staff-only tool (not a customer upload page), no link to a job record, the column rules and 12 per page.
