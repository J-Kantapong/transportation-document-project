# Plate swap (การสลับเลข)

Project documentation for Claude Code and Codex. Moved here unchanged from `CLAUDE.md` on 2026-11-16 to keep that file short; `CLAUDE.md` holds the index. Update this file when the feature changes.

- การสลับเลข (added 2026-09-22): split into `รถเก่า กับ รถใหม่` and `รถเก่า กับ รถเก่า` (the latter is an empty placeholder until the user gives its rules). Only cars for now; motorcycles come later. `รถเก่า กับ รถใหม่` stores one `PlateSwap` row per old vehicle (submit date, owner name, engine number, chassis number, brand, old plate, new plate, in that order; the user fixed this on 2026-09-23, engine and chassis are separate required fields here unlike `Vehicle`). Plates are stored as หมวดทะเบียน + เลขทะเบียน on both sides, matching `Vehicle`. The new plate is nullable: the office often doesn't know it when filing, so it can be filled in later from the submitted list or the return page (`PATCH /api/plate-swaps/:id/new-plate`) and both halves are required before confirming the return. A linked new vehicle carries the swap on its own record (`Vehicle.plateSwap` in the API, loaded separately from the vehicle query so a database without the table still works). On the submit-documents page that vehicle shows the swap, has its หมวด/เลข filled in automatically, and cannot be submitted until the swap's documents are confirmed returned (`PLATE_SWAP_PENDING_REASON` in `submission-eligibility.ts`)., a required link to a new vehicle in the new-registration database (`newVehicleId`, searched by chassis; changeable but never cleared), and a fee snapshot. `ยี่ห้อ` of the old vehicle is a dropdown of the `Brand` table, validated server-side. Fees live in `backend/src/plate-swap/plate-swap-fee.ts` (copied in `frontend/src/lib/plate-swap-fee.ts`); No Bill is ลงขัน 200 plus the old vehicle's ค่าอากร 10 (added 2026-09-23): the duty is counted in the No Bill total but excluded from the grand total, where it is shown on its own line. `dutyAmountOf` reads it back from a saved job's No Bill snapshot. Returning documents needs at least one receipt photo (`ReceiptImage.plateSwapId`) and a return date. API `/api/plate-swaps`, pages under `/registration/plate-swap/old-new` (`submit`, `return`), access = `ADMIN` / `STAFF_CAR` write, `ACCOUNTANT` read.

- Car urgent split (user 2026-11-18: the car ลงขัน 200 "already included urgent"): car No Bill is now ลงขัน 100 + ค่าอากร 10 + ลงขันด่วนเพิ่ม 100 when `urgent` (`PLATE_SWAP_CAR_URGENT_ITEM`); the car submit forms (old-new, old-old) tick งานด่วน by default, so the usual total is unchanged. `PlateSwap.urgent` is therefore used by cars too; migration `20261118180000_old_job_prices` sets `urgent = true` on every existing car row (flag only - `noBillItems` / totals snapshots keep "ลงขัน 200") so a later fee edit recomputes to the same 200. The edit dialog has the งานด่วน tick for both classes and shows the motorcycle plate item for motorcycles. A car job created through the API without `urgent` gets ลงขัน 100 only.

- เปลี่ยนเลขทะเบียน (user 2026-11-18, migration `20261118190000_plate_swap_kind_change` = enum value `PlateSwapKind.CHANGE`, additive): the customer reserves a number in the DLT system and puts it on one vehicle. "Works like plate swap but one vehicle" - so it is a `PlateSwap` row of kind `CHANGE` (no `newVehicleId`, no `pairId`) and reuses every later step of plate swap unchanged: รับใบเสร็จ (OCR, new plate required before confirming), รับป้าย, รับเล่ม (user: both steps exist), Delivery, vehicle search (labelled เปลี่ยนเลขทะเบียน), activity links. `POST /api/plate-swaps/change { vehicleClass, urgent, customerId, oldOwnerName, oldEngine, oldChassis, oldBrand, oldPlateCategory, oldPlateNumber, newPlateCategory?, newPlateNumber?, submitDate }`; lists / queues take `kind=CHANGE`. Fees (`calculatePlateChangeFees` in both fee files, user: "ใช้ราคาตามตารางได้เลย"): the plate is always bought and there is no auction / reserved option - car Bill 5 + 20 + 50 + 500 + 200 = 775, motorcycle 5 + 20 + 10 + 500 + 100 = 635; No Bill = plate swap's (car ลงขัน 100 + ด่วนเพิ่ม 100 ticked by default, motorcycle ลงขัน 100 + ด่วนเพิ่ม 50), ค่าอากร 10. The row stores `numberSource` NEW_UNUSED + `buyNormalPlate` true; `PATCH /:id` ignores those three options for this kind (only `urgent` recomputes fees) and `PATCH /:id/new-vehicle` answers 400. A new plate equal to the old one is refused. Pages `/registration/plate-swap/{car,moto}/change/{submit,receive-receipt,receive-plate,receive-book}` (`PlateChangeSubmitPage`, the other three are the plate-swap pages with `swapKind="CHANGE"`), listed third in the plate-swap menu of each class; page rule for the car path added in `auth.ts` (the motorcycle path is covered by `/registration/plate-swap/moto`), backend access = the existing `/api/plate-swaps` rule. Billing: on its own to the job owner as other-job type `PLATE_CHANGE` (see `billing.md`). Not built: overview / my-work / secretary labels still say สลับเลข for these rows.
- รับใบเสร็จ table layout (user 2026-11-19, "ไม่ต้องเลื่อน"): `ReturnRow` is 5 columns - วันที่ยื่น / เจ้าของงาน · รถเก่า (chassis first, then owner, brand, engine) · ทะเบียนเก่า / ใหม่ + รถใหม่ที่ลิงก์ · ใบเสร็จ (fields + photos) · รับกลับ (confirm, "ยังขาด: รูปใบเสร็จ · ทะเบียนใหม่" shown under a disabled confirm, then ✎ แก้ / ยกเลิก buttons). The receipt recheck boxes and the wrong-plate note sit in a full-width sub-row under each row. The table uses `.table-tight` (14px side padding, `globals.css`); fits at 1024 px with the sidebar open. Same layout on the other jobs' receipt pages (see `ui-conventions.md`).
