# Transfer notice receipt (step 2) and supplier route for other provinces

Project documentation for Claude Code and Codex. Moved here unchanged from `CLAUDE.md` on 2026-11-16 to keep that file short; `CLAUDE.md` holds the index. Update this file when the feature changes.

- Supplier route for out-of-province registration (user 2026-10-08, migration `20261008210000_supplier_province_route`, rule in `backend/src/document-submission/supplier-route.ts`, copied in `frontend/src/lib/supplier-route.ts`): `Vehicle.registrationProvince` alone decides who registers. กรุงเทพมหานคร (ตัดบัญชี) and สมุทรปราการ (แจ้งย้าย) = the office does all 8 steps; **every other province = the office does step 2 แจ้งย้าย, then a Supplier does the rest** (inspection, submission, pays the government fees, brings back receipt + plate + book). Such a vehicle skips the office inspection queue (`findPendingInspectionSend` excludes it, `updateInspectionSent` refuses it) and enters the Step 4 queue as soon as แจ้งย้าย is done: Step 4 for it = "ส่งงานให้ซับ" (`getSubmitBlockReason` ignores the inspection result / 90 days, submit date >= transfer completed date; `DocumentSubmission.viaSupplier` = true; `waitsFor` puts it at `submit` then `receipt`; the portal counts ตรวจรถ as done once handed over). Fees of such a submission: `billItems` = the normal computed Bill (estimate of what the supplier pays, compared with the DLT receipt the supplier returns, read by the existing receipt OCR), `noBillItems` = the supplier's fee from `SupplierProvinceRate` (ค่าดำเนินการซับ + ค่าช่อง + นำรถเข้าตรวจสภาพ, all three charged on every vehicle, except that since 2026-11-16 the Step 4 tick "ซับนำรถเข้าตรวจสภาพ" can be cleared when the customer takes the vehicle to inspection, making that line 0 - see `submit-documents.md`; no ค่าอากร / ลงขัน / ด่วน of the office). No rate row, an incomplete one, or `accepts = false` (พะเยา, แม่ฮ่องสอน) = the vehicle cannot be priced or handed over, with the reason shown in Step 4. The supplier fee is a cost only (never on the invoice; the selling price is the customer's own `ServiceFeeRate`, keyed in by the user). `SupplierProvinceRate` (province unique, accepts, serviceFee, channelFee, inspectionFee, plus plateSwapFee / plateSwapNote kept for reference only) was seeded from the supplier's price sheet (76 provinces; ปทุมธานี corrected by the user 2026-11-16 to ค่าดำเนินการ 200 / ค่าช่อง 200 / นำรถเข้าตรวจ 500 through data migration `20261116110000_supplier_rate_pathum_thani`, which also writes the AuditLog row); the supplier always charges per this table but may raise prices, so: `GET /api/supplier-rates` -> { rates[{ province, configured, accepts, serviceFee, channelFee, inspectionFee, total, plateSwapFee, plateSwapNote, note, updatedAt, updatedBy }], selfRegisterProvinces } (all staff), `POST /api/supplier-rates` { province, accepts, fees, plateSwapFee, plateSwapNote, note, remark, expectedUpdatedAt } (ADMIN, remark mandatory, 409 when stale, AuditLog entity `SupplierProvinceRate`), `GET /api/supplier-rates/history?province=`; page `/admin/supplier-rates`. Each submission snapshots the price of the day it was handed over, and a fee that differs for one vehicle is corrected on the receipt page ("✎ แก้" next to ค่าจ้างซับ): `PATCH /api/vehicles/document-submission/:id/supplier-fee` { serviceFee, channelFee, inspectionFee, remark } (PENDING or RECEIPT_RECEIVED, logged to VehicleEditLog). `computeDocumentFees(..., { billOnly: true })` is what billing uses for its receipt check. สมุทรปราการ inspection rate (office registers): motorcycles 200 in `FeeInspectionProvince`; จักรยานยนต์สาธารณะ (รย.17) 300 since the type was added the same day. Cars added 2026-11-17 (migration `20261117100000_inspection_rate_samut_prakan_cars`, user): รย.1 500, รย.2 1,000, รย.3 500, all brands (user: rough figures for now, may change); it is the No Bill cost default when the inspection send is saved, so vehicles already sent keep their saved cost. Not built / not decided: a separate job sheet for supplier jobs (they share the normal ใบยื่น groups), supplier SLA, the supplier's plate-swap prices. Not tested in a browser with a login (unit tests + a read-only run against the dev database only).

- แจ้งย้าย receipt at step 2 + into the bill (user 2026-10-08, migration `20261008220000_transfer_notice_receipts`, code `backend/src/transfer-notice-receipts/`, UI `frontend/src/components/TransferNoticeReceipts.tsx` on the transfer-notice page): a แจ้งย้าย job (registrationProvince not กรุงเทพมหานคร; ตัดบัญชี is unchanged and has no receipt) must have a แจ้งย้าย receipt before it can be ticked ดำเนินการแล้ว (`updateTransferNotice` answers 400, the tick box is disabled until then). One receipt covers one or many vehicles (the DLT sometimes issues one for several): `TransferNoticeReceipt` (file in the shared photo storage under `transfer-notice/`, image or PDF, `contentHash` unique, `totalAmount`) linked from `Vehicle.transferReceiptId`, with `Vehicle.transferBillCost` = that vehicle's share (split evenly in satang, remainder on the last vehicle; `amounts` may give per-vehicle shares that must sum to the total). For a vehicle with a receipt `Vehicle.transferCost` is the No bill part only (the page's cost box suggests the `FeeRelocate` No bill amount; the Bill no longer goes in that box); older rows without a receipt keep the old combined meaning. API (write = same roles as transfer notice: ADMIN / STAFF_ENTRY / STAFF_MOTO for motorcycles; read = all staff): `POST /api/transfer-notice-receipts` multipart `file`, `vehicleIds` ("id1,id2"), `totalAmount`, optional `amounts` JSON -> { id, totalAmount, vehicles[{ id, amount }] } (refused for a Bangkok vehicle, one that already has a receipt, or one already in a live invoice; may be attached after the step is done, so older vehicles can be backfilled before billing), `GET /:id`, `GET /:id/file`, `PATCH /:id` { totalAmount, amounts?, remark } (re-split), `POST /:id/detach` { vehicleId, remark } (only while that vehicle is not ticked done; total kept and re-split over the rest; last vehicle = receipt row and file deleted). Remark mandatory, every change logged to VehicleEditLog, nothing can change once any vehicle of the receipt is in a live invoice. `GET /api/vehicles/transfer-notice/*` rows carry `receiptRequired`, `transferBillCost`, `transferReceipt { id, totalAmount, vehicleCount }`. Billing (user: "รวมกันเลย จะได้ไม่ต้องเพิ่มคอลัมน์"): the bill keeps its two face lines; `createInvoice` copies `Vehicle.transferBillCost` into `InvoiceLine.transferReceiptAmount` under the vehicle lock (never taken from the client, kept unchanged by `updateInvoice` like `swapReceiptAmount`), `computeInvoiceTotals` / `computeTotals` add it to `feeTotal` (no VAT, not in the WHT base), the attachment's per-vehicle ใบเสร็จ column prints registration receipt + แจ้งย้าย receipt, and the billing queue row shows "+ แจ้งย้าย x" (`transferReceiptAmount`, `transferReceiptId` on queue vehicles) or "ไม่มีใบเสร็จแจ้งย้าย" for an out-of-province vehicle without one (information only). The แจ้งย้าย service fee is the existing per-customer `TRANSFER_NOTICE` add-on rate (e.g. 182.24, 95), already merged into ค่าบริการ. The overview counts `transferBillCost` as Bill of the transfer step. Not tested in a browser; the migration is not on the dev database yet. Waive the receipt (user 2026-10-19, migration `20261019100000_transfer_receipt_waiver`, additive): a job done outside the system or with no receipt can be ticked ดำเนินการแล้ว without one: the row has "ข้ามใบเสร็จ (ไม่มีใบเสร็จ)" + a mandatory reason; `PATCH /api/vehicles/:id/transfer-notice` takes `waiveReceiptReason` (blank = still 400 "ต้องแนบใบเสร็จ"), stores `Vehicle.transferReceiptWaivedReason` and writes a `VehicleEditLog` "ข้ามใบเสร็จแจ้งย้าย: <reason>" in the same transaction; any role that may save step 2 can do it (Claude's choice; ADMIN-only was the alternative). Rows then have `receiptRequired` false and carry the reason; undoing the status clears it; the vehicle has no `transferBillCost`, so nothing goes on the bill (billing shows "ข้ามใบเสร็จแจ้งย้าย", my-work `transfer-receipt-missing` skips it). A receipt can still be attached later. Not browser-tested (migration not applied to dev).
