# HR / payroll and 50 ทวิ issued by the company, suppliers

Project documentation for Claude Code and Codex. Moved here unchanged from `CLAUDE.md` on 2026-11-16 to keep that file short; `CLAUDE.md` holds the index. Update this file when the feature changes.

- HR / payroll (ฝ่ายบุคคล + เงินเดือน, user 2026-10-05, migration `20261005140000_hr_payroll`, code in `backend/src/hr/`, pages `/hr/employees`,
  `/hr/payroll`, `/hr/payroll/view?id=`): **ADMIN only, reads included** (`/api/hr` rule in `access-policy.ts`, `/hr` in `PAGE_RULES`; without the
  rule the catch-all GET rule would let every staff role read salaries). First round = employee register + monthly salary only (user's choice:
  no leave/attendance/OT, no documents, no loans). `Employee` is its own table (not `User`): code (TI001), prefix, first/last name, position,
  `idType` CITIZEN (13 digits) | OTHER (foreign workers, e.g. an 11-digit number), `idNumber` unique, birthDate, startDate, `baseSalary`,
  `socialSecurity` (per person, some are not enrolled), `withholdTax` (default OFF in the form and the Excel import: the company does not withhold tax from employees, user 2026-10-06; tick it per person if that changes), `otherAllowance` (yearly deductions beyond the personal 60,000),
  status ACTIVE | RESIGNED + `resignedDate`, optional `userId` link. Never deleted; edits need a remark and go to `AuditLog` entity `Employee`
  (salary changes included). Personal data is never seeded in the repo: the register has a paste-from-Excel import (`lib/hr-api.ts`
  `parseEmployeePaste`, columns: code, prefix, name, position, id number, (unused), birth date D/M/พ.ศ., salary, social security; blank or "-" =
  not enrolled), all-or-nothing, existing code / id number skipped. `PayrollRun` (`month` YYYY-MM, status DRAFT -> APPROVED -> PAID, soft cancel,
  one live run per month by partial unique index `PayrollRun_month_active_key`, `ssoRate` / `ssoWageCap` snapshot) with `PayrollItem` per person
  (snapshot of code / name / position; salary, otherIncome, otherDeduction, ssoAmount, taxAmount, netPay computed by the server; `ssoManual` /
  `taxManual` = typed over). Rules in `payroll-calc.ts` (Claude's reading of the law, check before the rules change): SSO 5% of salary, wage base
  floor 1,650, cap by year 15,000 (before 2026) / 17,500 (2026-2028, confirmed by the user's real sheet: 25,000 -> 875) / 20,000 (2029-2031) /
  23,000 (2032+); withholding (ภ.ง.ด.1) = projected-annual method: monthly income x 12 - expense 50% (max 100,000) - personal 60,000 - SSO (max
  9,000) - `otherAllowance`, progressive brackets, / 12 (a bonus month is only an estimate, the line is editable). Only DRAFT is editable
  (row-locked via a conditional `updateMany` on the run); unapprove / unpay / cancel / recalculate need a remark or confirmation and are logged to
  `AuditLog` entity `PayrollRun`; a PAID run must be un-paid before it can be cancelled; the pay date is mandatory from the start (user 2026-10-06): `POST payroll/runs` takes `{ month, payDate }` (between the 1st of the month and 62 days after its end, a future date is fine because slips are printed before paying), the screen defaults it to the last day of the month, `PATCH payroll/runs/:id/pay-date` `{ payDate, remark? }` edits it while DRAFT or APPROVED (APPROVED needs a remark, PAID must be un-paid first), a run without a pay date (older ones) cannot be approved, "บันทึกว่าจ่ายแล้ว" takes the actual date (<= today) and replaces it, and undoing a payment keeps the date; every payslip prints "วันที่จ่ายเงินเดือน" in the header. Employees included in a run: ACTIVE
  plus those resigned on/after the first of that month; no proration (edit the line). API `/api/hr`: `GET/POST employees`, `POST employees/import`
  { rows }, `PATCH employees/:id` { fields, remark, expectedUpdatedAt }, `POST employees/:id/resign` { date, remark } / `reinstate` { remark },
  `GET employees/:id/history`; `GET/POST payroll/runs` { month }, `GET payroll/runs/:id` (items + totals incl. `ssoRemit` = employee + employer
  share for สปส.1-10 and `tax` for ภ.ง.ด.1), `PATCH payroll/runs/:id/items/:itemId` { salary, otherIncome(+Note), otherDeduction(+Note), sso, tax
  (number = override, null = auto) }, `POST .../recalculate | approve | pay { payDate } | unapprove | unpay | cancel { remark }`, `GET .../history`.
  SSO schedule checked against the official announcement 2026-10-05 (5%; cap 17,500 from 2569, 20,000 from 2572, 23,000 from 2575). Payslips print from the run page (`lib/payslip-print.ts`, one per A4 page, black-and-white design, all dates in พ.ศ., also "save as PDF"; the tax row prints only when the amount is not 0; no year-to-date block on the slip because the system started mid-2569 and the totals would be too low, `items[].ytd` is still returned by `GET payroll/runs/:id` for later), CSV download of the run. Payer signature on payslips (user 2026-10-06, migration `20261006100000_payslip_signature`): `PayslipSignature` single row (id `payer`, `signerName`, `image` PNG bytes <= 300 KB / 1200x600 in the database, never in git); ADMIN uploads it in the panel at the top of `/hr/payroll` (`components/hr/SignaturePanel.tsx`; the browser first cleans the photo with `lib/signature-image.ts`: paper background -> transparent, ink -> black, cropped, <= 600x240); API `GET/PUT/DELETE /api/hr/payslip-signature` (`{ imageDataUrl: "data:image/png;base64,...", signerName }`, the server re-checks PNG magic + size, AuditLog entity `PayslipSignature` without the image). Every payslip then prints the signature, the name and the pay date (dotted when not paid yet) in the "ผู้จ่ายเงิน" block; "ผู้รับเงิน" stays blank for the employee. The same signature is printed in the "ผู้เสนอราคา" block of issued quotations (`buildQuotationHtml(q, { signature })`; not on DRAFT / CANCELLED / SUPERSEDED), read through `GET /api/billing/print-signature` (ADMIN + ACCOUNTANT, read-only; changing it stays ADMIN-only under `/api/hr`), `lib/print-signature.ts`. Not built (user did not ask):
  bank account / transfer file, leave and attendance, bonus tax special case, year-end 50 ทวิ for employees, ภ.ง.ด.1 / สปส.1-10 forms, linking
  salaries to the cash ledger.

- 50 ทวิ issued by the company (user 2026-10-06, migration `20261006200000_issued_wht_certificates`, code in `backend/src/hr/wht-issue*.ts`, page
  `/hr/wht`, print `frontend/src/lib/wht-certificate-print.ts`): the certificate the company gives to people it paid, NOT the `WhtCertificate` table
  (that one is what customers send us). **ADMIN only** (under `/api/hr`); menu: งานบัญชี > "Withholding Tax" and "Suppliers" (user 2026-10-06; the URLs stay `/hr/wht` and `/hr/suppliers` and the access stays ADMIN because the employee part reads salaries; letting ACCOUNTANT issue the sub certificates would need the sub part split from the employee part). Two payee kinds: `EMPLOYEE` = year-end, one salary line built by the
  server from `PayrollItem` of runs that are PAID with `payDate` in the tax year (the client never sends amounts; date label "ม.ค. - ธ.ค. 2569",
  SSO column from the same rows; form ภ.ง.ด.1ก) and `OTHER` = individuals such as subcontractors, typed by hand (ภ.ง.ด.3; lines SERVICE (item 5,
  needs a description) / FEE / ROYALTY / INTEREST / OTHER, no SALARY; tax id must pass the Thai 13-digit checksum; "WITHHOLD" with no tax at all is
  refused). Juristic payees (ภ.ง.ด.53), dividends and the monthly ภ.ง.ด.1 are not built. `Employee` has no address column, so an employee
  certificate prints a dotted address line. Number `{tax year}-{3 digits}` such as `2026-001` for tax year 2026 (`IssuedWhtCertificate.certificateNo`, same format as the user's old Google-file series; 2026-001 to 2026-008 were issued outside the system) and `IW{tax year}-{3 digits}` such as `IW2027-001` from tax year 2027 (user 2026-10-06: the old format only lasts to the end of 2026; `formatCertificateNo`; the tax year, not the issue date, decides, so year-end certificates for 2026 issued in January 2027 are still `2026-xxx`), taken under
  `pg_advisory_xact_lock` per tax year after `max(IssuedWhtSeries.lastNumber, highest number in the system)`: ADMIN sets `lastNumber` once per year while that year has no system certificate (`GET/POST /api/hr/wht/series` `{ year, lastNumber, remark }`, AuditLog `IssuedWhtSeries`; the page has a panel for it, **set 8 for 2026 before issuing the first one**); issue date <= today and not before the tax year. Never edited: cancel `POST /api/hr/wht/:id/cancel`
  `{ remark }` (number kept as CANCELLED, AuditLog entity `IssuedWhtCertificate`, every issue also logged as `issue`), then reissue; an employee has one
  live certificate per tax year (partial unique index `IssuedWhtCertificate_employee_year_active_key`), and a reissue links `replacesId` (unique, one
  replacement per cancelled certificate). Payer data is a snapshot of `SELLER_PROFILE` (keep in step with `COMPANY_PROFILE`). API: `GET /api/hr/wht?year&kind&q`
  -> { certificates, truncated }, `GET /api/hr/wht/employee-year?year` -> { rows (per employee: income, sso, tax, months, periodLabel, idValid,
  certificate), unpaidRuns }, `POST /api/hr/wht/employee-year` { year, issueDate, employeeIds } -> { created, skipped[{ name, reason }] } (skips
  already issued, nobody paid, bad citizen id), `POST /api/hr/wht` { taxYear, issueDate, payeeName, payeeTaxId, payeeAddress, payMethod, items[{
  incomeType, description, paidDate, amountPaid, taxWithheld }], note, replacesId? }, `GET /api/hr/wht/:id`, `GET /api/hr/wht/:id/history`.
  Print (`lib/wht-certificate-print.ts`): laid out after the user's own sample certificates (the full official form incl. the 4(ข) dividend rows, 13-digit id boxes, grey amount-in-words box, footnotes), A4 black and white, one page that fits exactly, printed as 2 identical pages per certificate (both ฉบับที่ lines are on every page, like the sample). **Dates are Gregorian (24/1/2026) and the employee period label is "ม.ค. - ธ.ค. 2026", as in the user's samples** (not พ.ศ.). The payer signature + name from the stored payslip signature (`GET /api/hr/payslip-signature`, the same one as payslips and quotations) is printed above the ลงชื่อ line when one is uploaded (user 2026-10-06 asked to remove it, 2026-10-08 asked to put it back; nothing is printed when none is stored), "ยกเลิก" watermark on cancelled ones. The "เล่มที่" field stays dotted.
  **Print copy of the official form (user 2026-10-06: "ก๊อบให้เหมือนกันเป๊ะ")**: the print now uses the Revenue Department form image `frontend/public/forms/wht-50tawi-blank.png` (300 dpi, rendered from the user's own fillable PDF with the form fields hidden, so it holds no personal data) as the background and overlays the values at the exact field rectangles of that PDF (`frontend/src/lib/wht-form-layout.ts`: coordinates in pt, values in Microsoft Sans Serif ~10pt, 17-cell comb for the 13-digit ids, ✔ in the check boxes, amounts right aligned, payer text as in the old certificates: name without "(สำนักงานใหญ่)" and the abbreviated address). Checked with a pixel overlay against the original PDF. Fits one line per type except item 5 (up to 4 lines); a certificate with more lines than the form has rows falls back to the older generic layout so nothing is dropped. Item 5 has no description field on the form (its text already says ค่าจ้างทำของ), item 6 prints its description in the (ระบุ) line. The print needs the image reachable at `/forms/...` of the same origin.
  Supplier register (user 2026-10-06: "ทำตามนี้เลย แยกจากพนักงาน", same migration, `backend/src/hr/supplier.service.ts`, page `/hr/suppliers`, ADMIN only under `/api/hr`): `Supplier` = individuals that are not employees (subcontractors) with name, 13-digit tax id (unique, checksum), address, default income type / description / withholding rate % (defaults only fill the issue form, never SALARY), status ACTIVE | INACTIVE. Never deleted; add / update / deactivate / reactivate log to AuditLog entity `Supplier` (update, deactivate and reactivate need a remark, update carries `expectedUpdatedAt` -> 409 when stale). API: `GET /api/hr/suppliers?status&q`, `POST`, `PATCH /:id`, `POST /:id/deactivate | reactivate` { remark }, `GET /:id/history`. The issue dialog has "เลือกจากทะเบียน" (active ones) which fills name / id / address and the first line's defaults; `POST /api/hr/wht` takes an optional `supplierId` (stored on `IssuedWhtCertificate.supplierId`, must exist) but the certificate still stores the typed name / id / address as its own snapshot, so editing a supplier never changes an issued certificate. Employees are not in this register (they have `Employee`).
