# Executive overview, work activity page, my-work page

Project documentation for Claude Code and Codex. Moved here unchanged from `CLAUDE.md` on 2026-11-16 to keep that file short; `CLAUDE.md` holds the index. Update this file when the feature changes.

- Work activity page (ภาพรวมการทำงาน, user 2026-10-08, no migration, `backend/src/activity/`, page `/activity`, menu item under ภาพรวม, ADMIN only because it shows prices): a read-only, time-ordered list of everything that happened on one Bangkok day, each row linking to the page where it can be checked. `GET /api/activity?date=YYYY-MM-DD` -> { date, today, prev, next, events[{ id, at, timed, type, group new|other|billing|edit, title, kind car|moto|null, cancelled, ref, customer, detail, bill, noBill, duty, amount, actor, href }], counts, kinds { car, moto }, totals { bill, noBill, duty, spend = bill + noBill, invoiced, collected } }. Sources: vehicle entry / submission / delivery slip / invoice / tax invoice / jobs (plate swap, tax renewal, Yamaha, transfer, use cancellation, plate copy, move out) by `createdAt`; receipt, plate and book received and invoice paid by their date-only columns (`timed` false, shown "—"); edits and cancels from `VehicleEditLog` + `AuditLog` with who and the reason. `kind` (user 2026-10-08 "แยกประเภทรถด้วย") comes from `Vehicle.body` (`vehicleKindOf`), the job's `vehicleClass`, the tax renewal's `vehicleType` and the delivery slip's items; null for money documents, Yamaha and general audit rows. Cancelled / voided bills stay listed (struck through) but are left out of the totals. Prices are the stored snapshots (submission Bill = `billValueOf`), duty kept apart and out of the total like everywhere else. Author columns (user 2026-10-08 "ช่องผู้ทำ", migration `20261008220000_work_authors`, nullable, rows before it stay NULL): `Vehicle.createdById` (who keyed the vehicle, set only in the create path, never on edit), `DocumentSubmission.createdById` (who submitted) and `receivedById` (who recorded the receipt, cleared when the submission is marked FAILED); the activity page shows them as the actor and the secretary evening card counts them per person. More author columns (user 2026-10-15 "ทำไมไม่มีชื่อผู้ทำ", migration `20261015120000_activity_authors`, plain `String?` user ids with no FK, rows before it stay NULL): `Vehicle.plateReceivedById` / `bookReceivedById` (set by the plate / book attach, cleared by detach), `Invoice.createdById` (all three issue paths) and `Invoice.paidById` (markPaid and the tax-invoice issue that marks it paid; cleared by unpay / TV cancel), `createdById` on PlateSwap, TaxRenewal, YamahaRelocationEntry, VehicleTransfer, VehicleUseCancellation, PlateCopy, VehicleMoveOut; the activity page also shows `TaxInvoice.createdById` (and "ออกก่อนรับเงิน"). The page resolves these ids with one User lookup and shows "ไม่ทราบ" for a row without an author (keyed before the column existed, or fixed by a script). Every AuditLog entity / action written by the code has a Thai label and a link to the page where it can be checked (`AUDIT_*_LABELS` / `auditHref`; `activity.service.spec.ts` scans the source and fails when a new literal has no label); plate-swap rows link to `/registration/plate-swap/{car|moto}/{old-new|old-old}` (the old `/registration/plate-swap/old-new` link was a dead page). Still without an author: inspection and transfer-notice steps, quotations, payroll. Claude's choices: grouping and which events count.

- Executive overview (added 2026-09-24, branch feature/overview): `/` renders `ExecutiveOverview` for `ADMIN` only (`HomeDashboard` picks by token roles); other roles that can open `/` (ACCOUNTANT) still see the old placeholder until the user defines their own overview. API `GET /api/overview?date=YYYY-MM-DD` (ADMIN-only, read-only) in `backend/src/overview`: daily spend (Bill/No bill from submissions, inspections, transfers, plate swaps, tax renewals, Yamaha), cash collected (Invoice PAID) and billed, money tied up (in process / delivered-unbilled / receivable + aging), a 4-week cash forecast from customers' real days-to-pay, a per-step table split car/motorcycle (done on the chosen day, cost that day, backlog now, oldest, over-SLA; plus plate swap, tax renewal, Yamaha unsplit), a "รถที่ติดขัด" list of individual vehicles over SLA or flagged (inspection failed/expiring/expired, submission failed, receipt missing with unknown cause, waiting on a plate swap), and action alerts. Each vehicle's current queue comes from `waitsFor` in `backend/src/overview/overview-process.ts`, which mirrors the real queue rules. SLA days per step, the 14-day inspection-expiry warning and the forecast defaults are Claude's choices (`STAGES` in `overview-process.ts`, constants in `overview-calculator.ts`); there is no bank balance, so cash is shown as net flow only. The receipt step (done on the day, receipt-vs-Bill series, and the start of the plate/book wait) uses `DocumentSubmission.receiptDate`, the date printed on the receipt (user's choice 2026-09-25), falling back to `receiptReceivedDate` then `submitDate`.

- Overview alerts go to the vehicle (user 2026-10-09 "อยากให้คลิกแล้วไปที่คันๆนั้นเลย", no migration): the per-vehicle alerts of `GET /api/overview` (`inspection-expiring`, `submission-failed`, `inspection-redo`, `receipt-unknown`, `receipt-late`, `delivery-pending`, `billing-late`, `plate-owed`) carry `items` (same shape as `stuck.items`, the 50 most urgent, `ALERT_ITEM_LIMIT`) and `itemTotal`. Both the count in the alert text and the list come from one list of every late / flagged wait (`problemItemsFor` in `overview-process.ts`; a vehicle can be in several alerts, unlike the stuck list which keeps one row per vehicle), so they always agree. On the page (`AlertRow` in `ExecutiveOverview.tsx`, `AlertItems` in `OverviewProcess.tsx`) one item = "ไปที่คันนี้" straight to that vehicle, several = "ดู N รายการ" expands a table with a `?focus=` link per row (`stuckHref`, shared with the stuck list; job items waiting for delivery now also get `?focus=`). `FocusVehicleRow` also matches elements marked `data-focus-row` (the billing queue rows are divs, so focus used to answer "ไม่พบรถ" there), looking there before table rows. Round 2 (same day): the document alerts carry `docs[{ id, title, customerName, amount, dateLabel, date, note, href }]` + `itemTotal` instead of `items` (`AlertDoc` in `overview.service.ts`, `DocTable` on the page), with the link built by the backend: `ar-overdue` / `ar-past-due` / `ar-due-soon` -> `/accounting/billing?focus=<invoiceNo>`, `wht-overdue` -> `/accounting/tax-invoices/wht?focus=<TV no>` (the page opens that customer's group), `quotation-*` -> `/accounting/quotations/view?id=`, `receipt-variance` -> the receipt page of that vehicle kind with `?focus=<chassis>` (a vehicle not in the pending sheets is searched in the "ได้ใบเสร็จแล้ว" table), `tax-missing` -> `/submit-documents/records?date=&tab=&focus=`. So `?focus=` is no longer only a chassis: `FocusVehicleRow` matches the value as a whole token per text node (`IV2026-12` must not highlight `IV2026-121`, and `-` counts as part of a number) and its not-found message is neutral. Only `pending-users` has no list. Not browser-tested for lack of dev data: the `delivery-pending`, `wht-overdue` and quotation links.

- Overview duty (user 2026-10-05): the executive overview's spend totals leave out ค่าอากร, as the submit review page does. It reads the duty from the stored `noBillItems` (labels starting `ค่าอากร`, `dutyOfItems` in `overview-calculator.ts`) for submissions, plate swaps and tax renewals, takes it out of `noBill`, and returns it apart: `spend.*.duty`, `cash.daily[].duty`, `spend.categories[].dutyToday/dutyLast30`, `process[].duty` (null where a step has none). The page shows it on its own line (KPI card, daily table, category table, process table footer). The jobs with their own `dutyAmount` column are covered since 2026-10-06 (below).

- Overview update for the newer flows (user 2026-10-06 "Flow มากขึ้นแล้ว", no migration, `backend/src/overview/`): spend categories `vehicleTransfer` (งานโอน), `useCancel`, `plateCopy`, `moveOut` read the stored `billTotal` / `noBillTotal` / `dutyAmount` snapshots by `submitDate` (their `noBillTotal` already excludes duty, unlike plate swap / tax renewal), cancelled rows left out, and so flow into the daily series, the 30-day comparison and the forecast average. The process table has rows for each (submitted that day, spend, duty, waiting) plus งานโอนตรวจรถ send / result and คัดป้าย receive-plate; waiting = receipt not returned (`returnedDate` null), plate copy also plate not received, inspection transfer waits per `transferWaits` (FAIL goes back to send, flagged `INSPECTION_FAILED`). New stage keys `useCancel`, `moveOut`, `plateCopy`, `plateCopyPlate` (SLA 21 calendar days = 15 working days, `PLATE_COPY_EXPECTED_CALENDAR_DAYS`), `transferInspectSend`, `transferInspectResult`, `transferJob` (SLAs are Claude's defaults), and stuck items with `source: 'otherJob'` carry their own `href` to the return / receive-plate page. Plate swap now splits by `vehicleClass` (cars and motorcycles) instead of cars only, and so do the two plate-copy rows (2026-10-09; they used to report `moto: null`). New alerts, sorted high > medium > info: bills past their credit `dueDate` (under 60 days; over 60 stays the existing high alert), bills due within 7 days, customer 50 ทวิ overdue (`WHT_OVERDUE_DAYS`), quotations approved but not billed / applied, quotations expired or waiting. Company expenses (user 2026-10-06 "เอารายจ่ายทั้งหมดเข้าไป") count in the spend total as `overhead` (`spend.*.overhead`, `cash.daily[].overhead`, kept apart from Bill / No bill / other): categories `payroll` (PAID `PayrollRun` by `payDate`: salary + otherIncome + the employer SSO share = `ssoAmount`, not net pay) and `subcontract` (`IssuedWhtItem.amountPaid` of ISSUED certificates with `payeeKind` OTHER by `paidDate`; employee year-end certificates are skipped so salary is not counted twice). `backend/scripts/analyze-stage-durations.mjs` (read-only, aggregate numbers only) prints how long each stage really takes, to set the SLAs in `STAGES` from production data (not done yet: dev data is test data). Not in the overview yet: cash advance (stashed), tax invoices as cash (cash still = `Invoice` PAID), the money tied up in these jobs (`workingCapital` unchanged, basis still undecided).

- My work page (งานของฉัน, user 2026-10-13 "ภาพรวมให้พนักงานแต่ละ Role ในการจัดการเอกสารที่ติดขัด เรียนรู้จากข้อผิดพลาด", no migration, `backend/src/my-work/`, page `/my-work`, `frontend/src/components/MyWorkPage.tsx`): a read-only per-role overview with no office prices. `GET /api/my-work` (all staff roles + DELIVERY; the service reads the roles from `currentUser()`) -> `{ today, roles, summary, problems[], problemTotal, checks[], stages[] }`. (1) "ต้องจัดการก่อน" = the overdue / flagged waits of the vehicles and jobs the role is responsible for, built from the same `waitsFor` / `transferWaits` / `plateCopyWaits` / `problemItemsFor` as the executive overview (the open-work selects in `my-work.service.ts` are a copy of those in `overview.service.ts`, keep them in step), filtered by `isMine(roles, stage, kind)` in `my-work-roles.ts`: STAFF_ENTRY = transfer / inspectSend / inspectResult all kinds; STAFF_CAR / STAFF_MOTO = submit .. plateDelivery + every other-job stage + jobDelivery in their kind (STAFF_MOTO also `transfer` for motorcycles); ACCOUNTANT = billing + the delivery stages (they record deliveries from the billing page); DELIVERY = delivery stages; ADMIN = all; a user with several roles gets the union per stage. Every row carries a ready `href` (`workHrefFor`, a copy of the frontend's `workPageFor` with `?focus=`; ACCOUNTANT without a delivery role is sent to `/accounting/billing` instead of `/delivery`). (2) "ตรวจก่อนผิด" = checks derived from the mistakes that repeat in VehicleEditLog / AuditLog / failed submissions (dev data 2026-10-13: slip date wrong 61, submit date wrong 30, "ป้ายไม่มา" slip cancels 61, CC / body wrong 10, brand wrong 13, owner province wrong 20), each with a `lesson` text and an owner (`entry` / `submit` / `delivery` / `accounting`, `hasCheckOwner`): `moto-cc-mismatch` (high, `motorcycleCcMismatch` on vehicles not yet submitted), `transfer-receipt-missing` (แจ้งย้าย done within 60 days, no `transferReceiptId`, not billed), `other-province` (info, registrationProvince ≠ ownerProvince before submission), `missing-owner` (info), `submission-date-drift` (PENDING submissions of the last 14 days whose submit date is before the Bangkok date of `createdAt`, or more than 7 days after it; keying in advance is normal and not flagged), `receipt-variance` (receipt ≠ `currentBillEstimate`, 30 days), `slip-date-drift` (DL slips of the last 14 days dated more than 2 days before or 7 days after `createdAt`, link `/delivery/report?focus=DL-xxxxx`), and for accounting `ar` (ISSUED invoices over 60 days = high, past `dueDate` = medium, due within 7 days = info), `wht-overdue` (TV with WHT and no 50 ทวิ after 30 days), `quotations` (approved but not billed / not applied, expired, waiting). Checks are sorted high > medium > info, 50 rows each + `total`. (3) "คิวของฉัน" = `summarizeBacklog` of the role's waits per stage. Frontend: `lib/my-work-api.ts`, styles `mw-*` in `globals.css`, menu "งานของฉัน" for every non-customer role, `PAGE_RULES` `/my-work` = `MY_WORK_ROLES`; `homeFor` now sends every staff role (not ADMIN / CUSTOMER) to `/my-work` after login, and `/` for ACCOUNTANT renders `MyWorkPage` instead of the old placeholder. The page reloads on window focus. Browser-tested on dev as ADMIN only (role filtering is unit-tested in `my-work-roles.spec.ts`). Claude's choices: the role -> stage table, the thresholds (14 / 7 / 2 / 60 days), landing staff on this page, and which mistakes became checks; the known-model (brand / CC by chassis prefix) warning of `vehicle-data-check.ts` is not on this page yet.
