# LINE bots: personal secretary, customer bot, statement and Yamaha mail

Project documentation for Claude Code and Codex. Moved here unchanged from `CLAUDE.md` on 2026-11-16 to keep that file short; `CLAUDE.md` holds the index. Update this file when the feature changes.

- Personal secretary on LINE (เลขาส่วนตัว, user 2026-10-07, migration `20261007200000_secretary_notes`, code in `backend/src/secretary/`, backend only, no web page): a LINE Official Account bot talks to the owner's personal LINE only (env `LINE_CHANNEL_ACCESS_TOKEN`, `LINE_USER_ID`, `LINE_CHANNEL_SECRET`, see `.env.example`; never commit or paste them in chat). Push: `SecretaryService.sendMorning` / `sendEvening` build Flex cards from `OverviewService.overview()` (no AI, no tokens); morning = overdue bills, stuck vehicles, yesterday's spend, customers past due, top alerts; evening = today's spend, problems (high alerts), what each step did, staff activity, tomorrow's reminders. Staff names come from where the system records who did it: vehicle entry, submit and receipt-received (author columns since 2026-10-08), VehicleEditLog / AuditLog editors and DeliverySlip.createdBy; plate / book received and the other jobs have no author yet. Amounts are exact, not rounded. Cards list everything (user 2026-10-08 "ข้อมูลควรครบก่อน", replacing the earlier 3-5 line limits): every problem, every step done, every staff member, every overdue customer and reminder; `SECTION_MAX` (15 lines per section, `card-parts.ts`) only keeps the bubble under LINE's 30 KB, and whatever exceeds it follows as text messages (`overflowTexts`), so `buildMorningMessage` / `buildEveningMessage` return `LineMessage[]`. Cards link to web pages when `FRONTEND_ORIGIN` is a real URL (`urlFor` in `card-parts.ts`; alert `href`s come from the overview). The overview now also returns `workingCapital.overdue` { count, amount, customers[{ customerName, count, amount, maxDaysOver }] } = invoices past `Invoice.dueDate` (`overdueByCustomer`). Chat (plan A, keyword commands, user's choice): LINE posts to `POST /api/secretary/webhook` (PUBLIC in `access-policy.ts`, every other `/api/secretary` route ADMIN), which first checks `X-Line-Signature` against the raw body (`NestFactory.create(..., { rawBody: true })`, `line-webhook.ts`; 401 without a valid signature, 503 if `LINE_CHANNEL_SECRET` is unset), answers LINE at once and replies in the background (reply token, falling back to push); only events from `LINE_USER_ID` are answered. Commands (`commands.ts`, `replies.ts`): สรุปเช้า, สรุปเย็น, ค้างจ่าย, รถติดขัด, ยอดใช้จ่าย, คำสั่ง (help), plus quick-reply buttons. Note vault (`SecretaryNote`, `notes.ts`, `NotesService`): `จำ <ชื่อ> = <ข้อความ>` (same name overwrites and returns the old value), `ขอ <ชื่อ>` (exact, else contains), `ลืม <ชื่อ>` (exact only, returns the deleted value), `ตู้เอกสาร` (list); max 200 notes, no passwords or ID numbers. Manual sends: `npm run secretary:test | secretary:morning | secretary:evening` in `backend/`. Schedule (user 2026-10-07: morning 09:00, evening 16:00 Thai time): `.github/workflows/secretary.yml` calls `POST /api/secretary/run?slot=morning|evening` (PUBLIC in `access-policy.ts`, guarded by header `x-secretary-key` = env `SECRETARY_RUN_KEY` >= 16 chars, 503 when unset, 401 when wrong; `run-key.ts`), because the Render free plan sleeps and an in-process cron would miss. The same slot on the same Thai day sends once (in-memory guard against retries, `runScheduled`). GitHub only runs schedules from the default branch (master), so nothing fires from dev; the workflow needs repo secrets `SECRETARY_BACKEND_URL` and `SECRETARY_RUN_KEY`, and the manual "Run workflow" button only exists once the file is on master. Finance card (user 2026-10-31 "ส่งผ่านเลขาส่วนตัว", no migration, `finance-pending.ts` reads, `finance-message.ts` builds): "การเงินค้าง" is pushed as its own push right after the morning card (separate request because LINE takes at most 5 messages per push and a long morning card already has follow-up texts), and is returned for the command "การเงิน" / "การเงินค้าง" (quick-reply button added; `finance` is matched before `overdue` because the text contains ค้าง; "สรุปเช้า" in chat returns the morning card only). Lines only when non-zero, each linking to its page: payroll (previous month's run DRAFT / APPROVED, and the current month from day 20 when not PAID; a month with no run at all is only flagged for the current month), waiting for billing (same rules as the billing queue: delivered vehicles not in a live invoice and not closed + delivered other jobs not billed or closed; every customer listed, past `SECTION_MAX` in a follow-up text), receivables (every ISSUED invoice, company / personal split, oldest), 50 ทวิ pending (`WHT_PENDING_WHERE`, over 30 days / within 5 days of it), quotations (approved not billed / applied, expired, waiting, drafts), and on days 1-15 a reminder for last month's accounting package + ภ.พ.30 (the system cannot know it was sent). Thresholds (day 20, 5 days, 1-15) are Claude's choices. Previewed read-only against production data; not sent to LINE from here. Free-text questions with AI (plan B), file/photo vault and a Rich Menu are not built. Weekly reminders (user 2026-10-31 "ตั้งเตือนกันลืม", no migration, `backend/src/secretary/reminders.ts`): a fixed table `WEEKLY_REMINDERS` (weekday + Bangkok time + text + page link): Monday 16:00 วางบิล Lexus, Tuesday 16:00 เช็คยอด SPI ก่อนส่งงานวันพุธ, Wednesday 15:00 วางบิล Spac EV + MC Superbike, Friday 15:00 วางบิล T Double E. `POST /api/secretary/run?slot=reminder` sends every reminder of today whose time has passed and was not sent yet (one in-memory mark per reminder per day, so a retry or the daily evening run never double-sends); `secretary.yml` has cron lines `0 9 * * 1,2` and `0 8 * * 3,5` for it (a new reminder needs a row in the table and a cron line). Command "ตารางเตือน" (quick-reply button) lists the table; `npm run secretary:reminder` sends by hand. Not sent to LINE from here (today was a Saturday: nothing due).

- Secretary lookup commands + menu card (user 2026-11-18 "ข้อมูลเยอะขึ้นแล้ว ... อยากมองอะไรง่ายๆ / ดึงใบเสนอราคา ใบวางบิล ใบกำกับ / ราคาลูกค้า / ต้นทุนแต่ละงาน / งานค้าง", no migration, `backend/src/secretary/lookup.ts` pure + `lookup.service.ts` reads, all read-only, no AI): `handleEvents` order is now document links (`parseInvoiceLinkCommand`) -> `parseLookupCommand` -> notes -> `parseCommand`. Yamaha relocation and งานรถเก่า are not sections yet. `ราคา` = customers that have a `ServiceFeeRate` / `JobFeeRate` row, with one quick-reply button each (`withQuickReply` keeps a message's own buttons); `ราคา <ลูกค้า>` = that customer's base rates, add-ons (ขอใช้ / ด่วน), other-job rates and terms (VAT, WHT incl. the temporary special rate, credit days or pay weekday, quotation required). Cost sheets (user 2026-11-18 "อยากได้สรุปต้นทุนงานแต่ละแบบว่าคันละเท่าไหร่ พวก bill nobill เพื่อเสนอลูกค้า เช่น สลับเลข มีอะไรบ้างราคาเท่าไหร่", `job-cost-sheet.ts`, routing in `LookupService.cost`): `ต้นทุน` = list of jobs with one quick-reply button each; `ต้นทุน <งาน>` (`findCostSheet`: สลับ, โอน, คัด, ยกเลิก, ย้ายออก, ภาษี, ยามาฮ่า / แจ้งย้าย) = one text per job with every variant (car / moto, number source, copy type, transfer type): Bill items with total, No Bill items with total, "ถ้ามี" optional lines (plate, urgent, fine), ค่าอากร, and "จ่ายจริง = Bill + ต้นทุนเรา" where ต้นทุนเรา = No Bill + ค่าอากร. `COST_SHEETS` imports the constants of each job's `*-fee.ts`, so a rate change there changes the text (no numbers typed twice). `ต้นทุน จดรถยนต์` / `ต้นทุน จดจักรยานยนต์` (`ต้นทุน จด` = both) lists the `FeeCarBillParam` / `FeeCarNoBillParam` / `FeeMotorcycle*Param` rows from the database (annual tax not included). `ต้นทุน เฉลี่ย` = the averages below; any other word = supplier rate of that province. `ต้นทุน เฉลี่ย` = average real cost per job over the last `COST_DAYS` = 90 days (Claude's choice) with min / max / count: new registration by car / moto and จดเอง / ส่งซับ = `DocumentSubmission.noBillTotal` of RECEIPT_RECEIVED submissions + `Vehicle.transferCost` + `inspectionResultCost` when under `INSPECTION_SEPARATE_FROM`; other jobs (โอน / โอนตรวจรถ / โอนย้ายเข้า, ยกเลิกการใช้รถ, คัดแผ่นป้าย, ย้ายออก, สลับเลข, ต่อภาษี) = `noBillTotal + dutyAmount`, i.e. the user's rule cost = No Bill + ค่าอากร; receipt fees are left out (charged to the customer at cost); `VehicleTransfer.inspectionCost` is not included yet (its migration was not committed). `ต้นทุน <จังหวัด>` = `SupplierProvinceRate` (service + channel + inspection, "?" for an unknown box). `ใบเสนอราคาล่าสุด [n]` (3, max 5; ISSUED / APPROVED / REJECTED only), `ใบเสนอราคา QT2026-012` / a bare QT number, `ใบเสนอราคา <ลูกค้า>` = one text per quotation with the stored totals, status (expired shown), PO, bills made from it and a link to `/accounting/quotations/view?id=` (needs login; there is no public PDF link for quotations). `บิล <ลูกค้า>` / `ใบกำกับ <ลูกค้า>` = that customer's 5 newest through `StatementService.invoiceLinks` (`InvoiceLinkCommand` kind `customer`), same texts and 7-day links as "บิลล่าสุด"; when the word is not a customer the message falls through to the old commands (so "บิลเกินกำหนด" still answers overdue). `ยอด <ลูกค้า>` = open bills (‼ past due), billed / paid this month, delivered vehicles waiting for billing, open quotations ("ยอดใช้จ่าย" stays the spend command). Quick-reply buttons are now เมนู, งานค้าง, การเงินค้าง, บิลล่าสุด, ใบกำกับล่าสุด, ใบเสนอราคาล่าสุด, ราคาลูกค้า, ต้นทุนต่อคัน, เรทจังหวัด, คำสั่งทั้งหมด (สรุปเช้า / เย็น, ค้างจ่าย, รถติดขัด moved into the menu card; ยอดใช้จ่าย, ตู้เอกสาร, ตารางเตือน are typed). - Customer LINE bot (บอทไลน์ลูกค้า, user 2026-10-09, no migration, code in `backend/src/customer-line/`, backend only): a second LINE Official Account for customers ("Jitkusol Auto"), separate from the personal secretary account and with its own keys (env `LINE_CUSTOMER_CHANNEL_SECRET`, `LINE_CUSTOMER_CHANNEL_ACCESS_TOKEN`, see `.env.example`). `POST /api/customer-line/webhook` (PUBLIC in `access-policy.ts`, every other `/api/customer-line` route ADMIN) checks `X-Line-Signature` like the secretary webhook (401 without a valid signature, 503 when the secret is unset), answers LINE at once and replies in the background. It answers anyone who writes, so it never reads or writes vehicle or customer data and never shows the office's prices (the tax check below shows government tax only). Only feature so far (user's choice: chat bot, ตรอ. check only): a text containing "ตรอ" (spaces and dots ignored) gets two quick-reply buttons รถยนต์ / มอเตอร์ไซค์, each a LINE `datetimepicker` (postback data `tro:car` / `tro:moto`, max = today in Bangkok); the picked registration date comes back in the same postback, so no conversation state is kept, and the bot answers whether a ตรอ. inspection is needed, with the date from which it is (shown in พ.ศ.). The rule is read from `requiresInspection` of the tax renewal calculator (cars 7 years, motorcycles 5, date-to-date, due on the anniversary itself), plus a fixed note that tax overdue by more than a year always needs one. Since the menu below was added the bot answers every text message, so the auto-response messages of LINE Manager must be switched off (both would answer). The date can also be typed in the same message, Buddhist year accepted ("ตรอ รถยนต์ 15/03/2562", day/month/year with / - or ., a 2-digit year = พ.ศ. 25xx; `parseTypedTro`): with a vehicle word the bot answers for that kind, without one it answers for both kinds, and a bad or future date gets a format hint. The date picker only works in the LINE phone app. Bottom menu + button cards (user 2026-10-09 "แถบเมนูด้านล่างพร้อมการ์ดปุ่มกด", no migration): the document lists that were 13 keyword auto-responses in LINE Manager now live in `customer-menu.ts` (`MENU_CARDS`: welcome, documents, new registration + 4 cases, transfer, plate swap, colour change, tax renewal, plate copy, ตรวจนอก, forms with the 6 Drive links, staff contact = a call button to `CONTACT_PHONE`, the delivery slip's number, confirmed by the user) and are sent as Flex cards whose buttons send a keyword back as a normal message (or open a link / `tel:`), so no state is kept and typing the keyword gives the same card. `findMenuCard`: exact keyword first, else the longest keyword contained in the sentence (keywords under 4 characters only match exactly); a text that matches nothing and a `follow` event get the welcome card; images, stickers and unknown postbacks get no answer; ตรอ. is checked before the menu. If LINE refuses a card the same content is sent as plain text. Rich Menu (`rich-menu.ts`, image `rich-menu.png` 2500x1686 drawn from `rich-menu.html` with headless Chrome, copied to `dist` through `assets` in `nest-cli.json`): 9 areas (จดใหม่, โอนรถ, สลับเลข, เปลี่ยนสี, ต่อภาษี, คัดป้าย / แบบฟอร์ม, เช็ก, ติดต่อเจ้าหน้าที่), each a message action; `syncRichMenu` runs on boot when the access token is set, creates the menu named `jitkusol-main-<RICH_MENU_VERSION>`, uploads the image, sets it as the default for all users and deletes its own older versions (bump the version to change the image or areas; nothing happens when the current one is already the default). Claude's choices, not confirmed: the menu layout and artwork, answering unknown texts with the welcome card (it will get in the way if staff chat is ever switched on in LINE Manager). Tax check (user 2026-10-09 "ใส่ฟีเจอร์เช็คค่าภาษี ... อย่าลืมรถไฟฟ้า ... นิติด้วย ... ให้ใช้ง่ายที่สุด", `tax-check.ts`, no migration): "เช็กภาษี" / "ค่าภาษี..." / a text starting with "ภาษี" opens a card of vehicle kinds (`car` = รย.1 by CC incl. hybrids and 4-door pickups, `ev` = รย.1 BEV by weight, `pickup` = รย.3 by weight, `moto`, `emoto`), then the bot asks one thing at a time: CC or weight (typed number), owner บุคคลธรรมดา / นิติบุคคล (only `car` and `ev`, where a juristic owner doubles the tax; a financed car with an individual hirer is told to pick บุคคลธรรมดา), registration date (typed in พ.ศ. or picked), and "ภาษีขาดต่อหรือยัง": one tap "ยังไม่ขาด" (the due date is then taken as the next anniversary of the registration date, `nextAnniversary`) or the expiry date when it has lapsed. The answer is a card with the yearly tax (age discount shown), late surcharge, each overdue year when several are owed, the total payable to the DLT and the ตรอ. result. The amounts come from `calculateVehicleTax` of the tax renewal job with the rate tables from `TaxService.loadRuleSet()` (cached 10 minutes), as an individual-owner / juristic calculation with no finance exemption; it shows government tax only, never the office's prices, and reads no vehicle or customer data. Unfinished answers are kept per LINE user in memory (`TaxSession`, 20 minutes, max 2,000, lost on restart); while one is open a typed text is the answer to the current question unless it is ยกเลิก, a ตรอ. question, an exact menu keyword (a Rich Menu tap) or a new tax question. `routeEvent` in `customer-line.service.ts` holds this order and is what the tests cover. A kind with no rate row (today `emoto`: `GovernmentTaxMotorcycleFlat` has no BEV row, and an electric pickup is not asked about at all) is refused at the first step with "ติดต่อเจ้าหน้าที่". The Rich Menu tile and the card `check` offer both checks. Not tested against LINE itself (unit tests + a read-only run of the calculator against the dev rate tables; the keys exist on production only).

- Statement -> tax invoice from LINE (user 2026-11-16 "ผมชอบลืมออกใบกำกับ", no migration, `backend/src/secretary/`): the owner shares the K BIZ statement CSV (`recent_transaction_*.csv`: header row `Transaction Date`, `Transaction`, `Withdrawal (Baht)`, `Deposit (Baht)`, `Account/PromptPay or Biller`, `Channel`; no payer name) into the secretary chat. `handleEvents` now also takes `message.type = file` and `postback` events (owner only, redeliveries skipped). `bank-statement.ts` (pure): `parseKbizCsv` -> deposits, `matchDeposit` against ISSUED / PAID invoices of the last 12 months by amount only: the bill's net, or the gross less WHT 0 / 1 / 3 / 5 % of ค่าบริการ, a deposit may be up to 10 baht short (transfer fee, `FEE_TOLERANCE`) or 0.5 over, 2-4 ISSUED bills of one customer may add up, bills issued after the deposit date are ignored; a PAID bill with `paidDate` = the deposit date and a fitting amount = already done. `statement-message.ts` builds the reply: a summary text (to do / already recorded / no bill found) plus a carousel with one card per deposit to act on (max 12 per carousel, warning colour when several bills fit) and one button per bill: "ใบกำกับ IVxxxx" for a COMPANY + VAT bill without a live TV, else "รับเงิน IVxxxx" (personal-account bills, and bills whose TV was issued before payment such as YM). Postback data `st|tv|tvgo|pay|paygo|<invoiceId>|<deposit date>|<wht>`; every action is two taps: `tv` / `pay` answer a confirm card (next TV number, date = deposit date, WHT amount and method from `Customer.billingWhtMethod`, missing buyer data or series not enabled = no confirm button, a warning when the date is before the latest TV), `tvgo` calls `TaxInvoiceService.issue` (`paidDate` = deposit date, `backdateConfirmed: true`) and `paygo` calls `BillingService.markPaid`; nothing is ever issued without the second tap, and the service's own checks (status, date order, lock) still apply, so a double tap answers the conflict text. `BillingModule` exports `BillingService` + `TaxInvoiceService` for this; these calls run outside a request, so `createdById` / `paidById` are null. Tax invoice download links with amounts (user 2026-11-16 "อยากได้ลิ้งใบกำกับภาษีด้วย ... สรุปยอดมาด้วยพร้อมระบุหัก ณ ที่จ่าย vat เท่าไหร่"): "ใบกำกับล่าสุด" (2 newest ISSUED by `createdAt`, max 5) or "ใบกำกับ TV2026-146" (by number, max 5; a message mixing TV and IV numbers is not a command) -> same `parseInvoiceLinkCommand` (`doc: 'tv' | 'iv'`) -> `StatementService.invoiceLinks` -> one text per tax invoice: number, customer name from `customerSnapshot`, date, bill number, then one line each (format chosen by the user 2026-11-16 after trying a 5-line short form): ค่าธรรมเนียม / ค่าบริการ / ค่าสินค้า (only those above 0), VAT with its rate, รวมทั้งสิ้น (`grandTotal`), หัก ณ ที่จ่าย with its percent and amount (`whtAmount`; percent = `whtAmount` ÷ `serviceTotal` because the tax invoice stores no rate, omitted when there is no service amount; "ไม่มี" when 0), ยอดรวม (`receivedAmount` = after withholding; the user's wording, was "ยอดรับจริง"), and the `/tv` download link (token kind `tv`). Amounts are read from the tax invoice row, never recomputed. Phones (user 2026-11-16: on an iPhone the link showed the web page, no PDF file): mobile browsers do not let a page save a file by itself, so `/tv` and `/iv` share `components/DocumentLinkView.tsx`: on a touch device that can share files (`navigator.canShare`, coarse pointer) the PDF is built on load and the button "ส่ง / บันทึกไฟล์ PDF" opens the device share sheet with the real PDF file (send to LINE, save to Files); "เปิดไฟล์ PDF" opens it in the browser's PDF viewer as a fallback. The share sheet needs a tap, so it cannot open by itself. Desktop keeps the automatic download for `download=1`. Not yet confirmed on a real iPhone; if building the PDF in the phone browser proves unreliable the next step is a server-made PDF. Invoice download links (user 2026-11-16 "ลองส่งใบวางบิลที่ออกล่าสุดสองอันมาหน่อยทางไลน์"): the owner types "บิลล่าสุด" (2 newest non-VOID bills by `createdAt`; "บิลล่าสุด 5", max 5) or "บิล IV2026-155" (by number, max 5) -> `parseInvoiceLinkCommand` in `invoice-link.ts`, checked before the notes commands (the whole message must match, so "ขอ ที่อยู่" still goes to notes) -> `StatementService.invoiceLinks` (read-only) -> one plain-text message per bill with `<FRONTEND_ORIGIN>/iv?token=…&download=1&openExternalBrowser=1`. Token = same HMAC link as the tax invoice but kind `iv` (signed id prefixed `iv:`), so a tax-invoice link cannot open a bill and the reverse; 7 days. `GET /api/secretary/invoice?token=` (PUBLIC in `access-policy.ts`, 401 before any query) returns `{ invoice }` in the `/api/billing/invoices/:id` shape; page `/iv` (in `OPEN_PATHS`, no shell) shows the bill with ปริ้น / บันทึกเป็น PDF and auto-downloads `<IV no.> <customer>.pdf` when `download=1`.
